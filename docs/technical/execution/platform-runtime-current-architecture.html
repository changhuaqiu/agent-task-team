Platform Runtime 当前架构

按当前代码绘制 · 重点区分 Agent 执行、事件投递重试与终态后 Effect 重试

主链路

  • Inbox 中的 Command 激活 Agent，而不是 Agent 订阅 Event Bus
  • Coordinator 把 ACP 原始信号归一化为 canonical runtime.* 事件
  • 领域表仍是 Task、Review、Delivery、A2A 的事实源

事件投递可靠性

  • EventLog 先保存事件，Dispatcher 再异步分发
  • Dispatcher 重试的是 event × handler delivery
  • 它不等于重新运行 Agent，也不保证 Handler 的外部 I/O 原子性

Effect Outbox 边界

  • 只在 runtime.invocation.terminated 之后规划执行后待办
  • 当前覆盖 task sync、proof、evaluation、team log、A2A response/done
  • 提供 Todo 的恢复与重试，不提供 Agent invocation 的自动重启

当前缺口

  • Agent 执行中崩溃后的 durable retry 尚未由 Outbox 解决
  • 若要补齐，需要 Invocation lease、重启策略、checkpoint 与新旧执行 fencing
  • Socket、进程内状态和 timer 仍属于提交后的 best-effort 通知
