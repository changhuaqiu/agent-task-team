# 项目栏 UX 规范（root -> 项目树）

> 状态：可交付开发
> 日期：2026-05-04
> 适用范围：左侧项目栏 / 工作区项目切换区
> 相关实现：
> - `src/components/project/ProjectSidebar.tsx`
> - `src/components/project/ProjectWorkspace.tsx`
> - `src/components/project/ProjectCreateDialog.tsx`

## 1. 目标

本规范只定义左侧“项目栏”的 UX，不讨论中栏、右栏和全局信息架构重做。

本次改造目标有三个：

1. 让项目栏更接近 Trae 的使用习惯：像一个安静的工作区树，而不是项目卡片墙。
2. 让项目栏服务“任务管理”：用户一眼知道自己在哪个项目里，哪些项目值得切换，哪些项目有问题。
3. 保留产品人格，但只在关键位置表达：整体保持克制，当前选中项目带一点品牌感，不把整栏做花。

## 2. 结论

项目栏采用两层结构：

- 第一层：`root`
- 第二层：`项目`

整体形态从“项目卡列表”调整为“工作区树”。

这意味着：

- 左栏首先表达“当前工作区”
- 具体项目挂在 `root` 下面
- 用户通过点击项目切换上下文
- 项目栏不再承担大量摘要、消息预览或任务详情职责

一句话定义：

> 项目栏 = 工作区树 + 项目切换器 + 轻量项目健康提示 + 新建项目入口

## 3. 用户心智

用户在左栏只需要回答 4 个问题：

1. 我当前在哪个 `root` 下工作？
2. 这个 `root` 下有哪些项目？
3. 我当前正在看哪个项目？
4. 哪个项目值得我切过去处理？

项目栏不负责回答这些问题：

- 当前任务详细怎么推进
- Agent 正在说什么
- 风险明细是什么
- 具体执行日志是什么

这些内容属于中栏或右栏。

## 4. 信息架构

### 4.1 顶层结构

```text
root
  项目 A
  项目 B
  项目 C
```

### 4.2 `root` 节点职责

`root` 是工作区容器节点，不是项目对象本身。

`root` 只负责：

- 表达当前工作区名称
- 表达路径或路径别名
- 作为项目树的展开/收起入口
- 承接“新建项目”动作

`root` 不负责：

- 展示风险摘要
- 展示 Agent 摘要
- 展示聊天预览
- 展示任务状态全量统计

### 4.3 项目节点职责

项目节点是实际切换单位。

项目节点只负责：

- 展示项目名称
- 展示一行简短目标或副标题
- 展示轻量健康提示
- 作为切换当前项目的入口

## 5. 展示规范

### 5.1 `root` 节点显示字段

必须显示：

- `root` 标签或工作区名
- 路径别名，或可读形式的项目根目录名
- 展开/收起箭头
- `+ 新建项目`

可选显示：

- 项目总数，例如 `3`

不要显示：

- 阻塞数
- 任务总数
- 风险数
- Agent 数
- 多个状态 badge

### 5.2 项目节点显示字段

默认显示：

- 项目名
- 一行副标题或一句话目标
- 一个轻状态信号

轻状态信号有两种可选方案：

- 方案 A：状态点
  - 绿色：健康推进
  - 黄色：有待处理 / 有注意项
  - 红色：有阻塞
  - 灰色：空项目 / 未开始
- 方案 B：极简计数
  - 例如 `12 / 2`
  - 表示 `12 任务 / 2 阻塞`

本规范推荐折中方案：

- 非选中项目默认显示 `状态点`
- 当前选中项目额外显示 `任务数 / 阻塞数`

### 5.3 项目节点不显示的内容

不要在项目节点中加入：

- 最近消息预览
- Agent 列表
- 技能列表
- 账号状态
- 风险详情
- 迷你看板
- 长段目标描述
- 多排 badge

项目节点应该更像 IDE 中的对象项，而不是独立功能卡。

## 6. 交互规范

### 6.1 `root` 节点交互

- 点击 `root` 行左侧区域：展开/收起项目列表
- 点击 `+ 新建项目`：在当前 `root` 下创建新项目
- `root` 行本身不切换项目

### 6.2 项目节点交互

- 单击项目：切换到该项目
- 当前选中项目保持可辨识，不因 hover 而丢失选中态
- 次要操作仅在 hover 时出现，例如：
  - 删除
  - 更多操作
  - 重命名

### 6.3 危险操作

危险操作不常驻显示。

建议：

- hover 时显示垃圾桶或 `...`
- 删除前仍需确认

不建议：

- 每个项目右侧一直常驻危险按钮

### 6.4 排序规则

默认排序：

- 当前项目保持高亮
- 其他项目按最近活跃排序

不建议按创建时间固定排序，因为不符合实际任务处理习惯。

## 7. 状态设计

### 7.1 普通态

- 背景安静
- 标题清晰
- 副标题弱于标题
- 状态提示简洁

### 7.2 Hover 态

- 轻背景变化
- 文字对比度略加强
- 浮出次要操作

不应：

- 缩放
- 强阴影跳动
- 大面积色块闪烁

### 7.3 选中态

选中态是品牌感最适合表达的位置。

当前选中项目建议同时具备 4 个信号：

- 更明确的背景层
- 左侧品牌色高亮条
- 标题字重或对比更强
- 显示更完整的轻状态信息，例如 `任务数 / 阻塞数`

### 7.4 问题态

当项目存在阻塞：

- 可通过红色状态点提示
- 不建议整项做大面积红底

原则：

- 让用户能扫到问题
- 不破坏整栏的安静气质

### 7.5 空状态

当 `root` 下没有项目时：

- 显示一句轻量空态文案
- 紧跟一个清晰的新建项目入口

推荐文案方向：

- `这个 root 下还没有项目`
- `新建项目，开始当前工作区的第一项任务`

不要写成长篇引导文案。

## 8. 视觉原则

### 8.1 总体风格

项目栏整体应更接近 Trae 的安静列表感：

- 低噪音
- 清楚层级
- 当前上下文明确
- 单一主动作明显

### 8.2 人格表达方式

本产品强调强人格，但项目栏不能变成花哨卡片区。

项目栏的人格表达只放在：

- 当前选中项目
- 主按钮（如新建项目）
- 轻品牌色边条或柔和底色

不要把每一项都做成高饱和度品牌卡片。

### 8.3 层级建议

视觉优先级应当是：

1. 当前选中项目
2. 有阻塞项目
3. 普通项目
4. 空项目 / 未启动项目

这能帮助用户快速完成扫描。

## 9. 与当前实现的差异

当前 [`ProjectSidebar.tsx`](file:///Users/kk/agent-task-team/src/components/project/ProjectSidebar.tsx) 已有以下正确方向：

- 有新建入口
- 有项目列表
- 有任务数 / 阻塞数
- 有当前选中态

但仍有以下偏差：

- 当前是“项目卡片式列表”，不是“root -> 项目树”
- 说明性文案偏多
- 每个项目项还偏像卡片对象，而不是 IDE 风格树节点
- 当前选中项识别感不够像工作区中的“当前上下文”

## 10. 推荐落地方案

### 10.1 第一阶段：结构调整

- 增加 `root` 顶层节点
- 现有项目列表作为 `root` 的子列表
- 新建项目入口移到 `root` 行右侧，或保留在该行主要操作位

### 10.2 第二阶段：视觉调整

- 项目项从厚卡片改为更安静的树节点样式
- 当前选中项目增加品牌化高亮
- 非选中项目去除过重卡片感

### 10.3 第三阶段：信息收敛

- 默认状态信息更轻
- 仅当前选中项目展示更完整的任务数 / 阻塞数
- 次要动作 hover 才出现

## 11. 开发约束

开发实现时需要遵守：

- 不新增左栏的任务详情面板
- 不在项目项中加入聊天预览
- 不在左栏重复右栏风险摘要
- 不让 hover 覆盖选中态
- 不把 `root` 行做成摘要大盘

## 12. 验收标准

满足以下条件视为完成：

1. 左栏已经是 `root -> 项目` 的两层结构
2. 用户一眼能识别当前工作区和当前项目
3. 当前选中项目明显，但整体依然安静
4. 非选中项目信息密度较低，不像大卡片
5. 新建项目入口明确，位于 `root` 语义附近
6. 项目项只表达“项目切换 + 轻状态”，不承担详情职责
7. 删除等危险操作不常驻
8. 项目栏整体更接近 Trae 的工作区树心智，而不是 dashboard

## 13. 给开发的摘要

请把左侧项目栏按以下原则实现：

- 形态：工作区树，不是项目卡片列表
- 层级：`root` 在上，项目在下
- 作用：切换项目，不做详情面板
- 信息：项目名 + 一行短目标 + 轻状态
- 重点：当前选中项目的识别度和品牌感
- 风格：整体像 Trae，当前项像本产品

不要把项目栏继续做重、做满、做成第二个首页。
