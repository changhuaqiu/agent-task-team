# 项目栏项目项视觉与交互细则

> 状态：可交付开发
> 日期：2026-05-04
> 适用范围：左侧项目栏中的 `root` 行与项目行
> 关联主文档：
> - `docs/product/ux/2026-05-04-project-sidebar-ux-spec.md`

## 1. 文档目的

本文件是 [`2026-05-04-project-sidebar-ux-spec.md`](file:///Users/kk/agent-task-team/docs/product/ux/2026-05-04-project-sidebar-ux-spec.md) 的细化补充，专门定义：

- `root` 行长什么样
- 项目行长什么样
- 默认态 / hover / 选中态 / 问题态怎么表现
- 哪些信息什么时候显示
- 哪些操作放在哪里

目标是让开发无需再次推断视觉和交互细节。

## 2. 总体原则

项目栏中的对象项应更接近 Trae / IDE 风格的工作区树，而不是产品卡片列表。

因此必须遵守：

- 使用树节点语义，不使用厚重大卡片语义
- 默认态安静，选中态明确
- 非选中项只提供必要信息
- 当前选中项才承载品牌感强化
- hover 只做轻量增强，不做夸张动效

## 3. `root` 行规范

### 3.1 `root` 行角色

`root` 行是工作区头节点，不是项目对象。

它只表达：

- 当前工作区是什么
- 下面可以展开哪些项目
- 可以在这个工作区下新建项目

### 3.2 `root` 行布局

建议布局：

```text
[展开箭头] [root 图标] [root 名称 / 路径别名] [项目数]
                                      [+ 新建项目]
```

### 3.3 `root` 行必须包含

- 展开/收起箭头
- `root` 图标或目录图标
- 工作区名称或路径别名
- 新建项目入口

### 3.4 `root` 行可选包含

- 当前 `root` 下项目数

推荐形式：

- `3`
- 或 `3 projects`

但不要出现更多摘要。

### 3.5 `root` 行文案

优先显示：

- 可读工作区名

次要显示：

- 路径名或路径别名

如果路径过长：

- 只展示最后一级目录名
- 完整路径在 hover 时通过 tooltip 提供

### 3.6 `root` 行视觉

默认态应：

- 比项目行更像“组标题”
- 有轻背景或无背景
- 不要做厚卡片

hover 态应：

- 有轻背景变化
- 展开箭头和按钮更清晰

展开态应：

- 箭头方向变化
- 子项目缩进显示

### 3.7 `root` 行交互

- 点击左侧主体区域：展开/收起
- 点击 `+ 新建项目`：打开新建项目弹窗
- `root` 行不切换项目

### 3.8 `root` 行不要做的事

- 不显示任务总数、阻塞数、风险数
- 不显示 Agent 摘要
- 不显示聊天相关元素
- 不放多个操作按钮
- 不做成强人格主视觉区

## 4. 项目行规范

### 4.1 项目行角色

项目行是左栏中唯一的“上下文切换对象”。

用户看到项目行时，应该能快速完成：

- 扫描项目名
- 判断当前项目
- 判断哪个项目值得切换

### 4.2 项目行布局

建议布局：

```text
[状态点] [项目名]
         [一行短目标]
         [轻状态信息 - 仅选中项更完整]
                 [...危险/更多操作 - hover 出现]
```

### 4.3 项目行必须包含

- 项目名
- 一行短副标题或目标
- 轻状态信号

### 4.4 项目行可选包含

仅当前选中项目可额外显示：

- 任务数
- 阻塞数
- 简短状态标签，例如 `进行中`

不建议非选中项目常驻显示全部这些信息。

## 5. 信息显示规则

### 5.1 项目名

项目名是第一视觉重点。

规则：

- 单行显示
- 超长截断
- 始终比副标题更强

### 5.2 副标题 / 一句话目标

副标题是帮助判断项目内容的辅助信息。

规则：

- 单行显示
- 长文本截断
- 弱于项目名
- 不允许显示成长段描述

### 5.3 轻状态信号

轻状态信号优先用状态点表示：

- 绿色：健康推进
- 黄色：有待处理或临界提醒
- 红色：有阻塞
- 灰色：空项目 / 未启动

补充规则：

- 状态点始终可见
- 不应用一整排 badge 替代状态点
- 状态点的目的是“让用户扫一眼”，不是展示详细语义

### 5.4 当前选中项目的补充信息

当前选中项目可以额外显示：

- `12 任务`
- `2 阻塞`

展示原则：

- 信息足够帮助判断当前项目复杂度
- 但不要演变成迷你统计面板

### 5.5 非选中项目的信息限制

非选中项目默认不显示：

- 完整任务数
- 阻塞数详情
- 多个状态标签
- 过多元信息

这样做是为了维持列表扫描效率。

## 6. 状态细则

### 6.1 默认态

默认态表现：

- 中性背景或无背景
- 清晰项目名
- 辅助副标题
- 一个轻状态点

目标：

- 列表整体安静
- 用户能快速纵向扫描

### 6.2 Hover 态

hover 态表现：

- 背景轻微增强
- 标题对比度略提升
- 右侧次要操作浮出

hover 态不允许：

- 位移跳动
- 缩放
- 重阴影
- 颜色大幅变化

### 6.3 选中态

选中态是项目栏中唯一允许明显品牌化强化的对象态。

建议选中态由以下 4 个信号组成：

- 柔和品牌色背景
- 左侧品牌色细高亮条
- 标题字重或对比度增强
- 显示额外轻状态信息

选中态目标：

- 用户一眼知道“当前在这里”
- 选中态稳定，不被 hover 冲掉

### 6.4 问题态

问题态用于表示项目存在阻塞。

建议：

- 用红色状态点
- 选中项可额外显示 `2 阻塞`

不建议：

- 全行红底
- 大面积警告样式

### 6.5 空项目态

空项目指还未产生任务或尚未启动的项目。

建议：

- 灰色状态点
- 更弱副标题

可用文案方向：

- `还没有任务`
- `等待启动`

## 7. 次要操作规范

### 7.1 操作入口

项目行右侧只允许在 hover 时出现次要操作。

推荐入口：

- `...`
- 或垃圾桶图标

### 7.2 可包含操作

- 删除
- 重命名
- 更多

### 7.3 不允许的做法

- 常驻显示一排操作按钮
- 默认态就出现危险操作
- 次要操作抢过项目名视觉权重

## 8. 选中态与 hover 冲突处理

这是实现时必须特别注意的地方。

当某个项目已经是选中态时：

- 鼠标 hover 上去后，选中态必须仍然成立
- 不允许因为 hover 而看起来像普通项

实现要求：

- hover 色域和选中色域必须不同
- 选中项 hover 只允许轻微增强，不允许回退成通用 hover 样式

## 9. 缩进与树层级

因为采用 `root -> 项目` 结构，必须体现层级。

建议：

- `root` 行无缩进
- 项目行统一缩进一层
- 通过缩进和状态点建立“树节点”感觉

不要用：

- 厚卡片
- 大量外框
- 每项独立大阴影

来伪装层级。

## 10. 强人格的落点

本产品强调“强人格”，但在项目栏里要克制表达。

推荐落点：

- 当前选中项目的背景和边条
- `+ 新建项目` 的主按钮气质
- 少量品牌色点缀

不推荐落点：

- 所有项目都品牌化
- 每项都有强装饰
- 每项都有彩色块或角色化图标

一句话：

> 整体像 Trae，当前项像本产品。

## 11. 推荐开发拆分

建议开发拆为 3 个视觉单元：

1. `WorkspaceRootRow`
2. `ProjectTreeItem`
3. `ProjectTreeItemActions`

这样便于：

- 保持 `root` 与项目行语义区别
- 独立处理选中态和 hover
- 避免 `ProjectSidebar.tsx` 继续膨胀

## 12. 验收标准

项目项细则满足以下条件视为完成：

1. `root` 行与项目行视觉角色明显不同
2. 当前选中项目一眼可辨识
3. 非选中项目足够安静，适合快速扫描
4. 当前选中项带轻品牌感，但整体不花
5. 危险操作不常驻
6. hover 不覆盖选中态
7. 项目项看起来像工作区树节点，而不是卡片对象
8. 任务管理信息足够，但不过量

## 13. 给开发的摘要

请按以下原则实现项目栏中的对象项：

- `root` 行像目录头
- 项目行像树节点
- 默认态安静
- hover 态轻提示
- 选中态带品牌色强化
- 当前选中项才显示更完整状态
- 危险操作 hover 才出现
- 不把项目项做成大卡片
