# 团队记忆与协作关系记忆

## 1. 用户问题

多 Agent 虽然能看到当前聊天和任务，但完成一次交付后，决定、踩坑、纠正和有效协作方式容易随会话结束而消失。结果是下一位 Agent 仍需重新摸索，团队看起来“说了很多，但没有越做越懂”。

## 2. 产品对象

- **团队记忆**：项目内可共享、带来源、可纠错的决定、事实、经验和未闭环事项。
- **Agent 私有记忆**：某 Agent 的临时工作偏好或草稿，只对其本人可见。
- **协作关系记忆**：Agent 之间经过真实交接、评审和交付形成的工作关系事实。
- **人类关系记忆**：涉及用户、第三方人物、偏好和画像的私域信息；不属于第一期共享范围。

## 3. 核心流程

系统先发现一次“也许值得记”的机会，Agent 再明确提议、延后或放弃。只有通过证据和治理的内容才成为团队记忆；后续任务开始、交接、重试和评审时，只提示少量相关线索并允许按来源下钻。

## 4. 关系记忆决策

第一期需要关系记忆，但只做工程协作关系：谁向谁交接过什么、谁评审过谁、哪些组合在何类任务上有已验证经验。它帮助 Agent 选择协作者和调整交接包，不用于打分、排名、人格判断或模拟情感。

关系双方必须是当前团队可证明的 Agent；用户或第三方即使参与一次交接，也不会被悄悄转成 Agent 关系候选。次数表示真实持久化事件总数，证据列表可以有界展示，但不得把抽样数冒充总数。

涉及用户的“怎么相处”“用户是什么样的人”“第三方是谁”等信息风险更高，必须有独立审批、私密作用域和遗忘能力。在这些能力落地前，系统不得自动生成或共享人类关系记忆。

## 5. 成功标准

- Agent 在新任务中能召回相关旧决定和经验，而不是重复询问。
- 召回内容能回到 Task、Proof、A2A 或评审证据。
- 不相关或已退休记忆不进入当前上下文。
- 协作关系摘要能解释来源，不出现好感度、信任分或人格标签。
- 记忆带来的改善必须通过固定任务集比较返工、重复提问、错误复现和召回采用率，不能只以“写入条数”证明价值。

## 6. 不做范围

- 全量聊天永久共享。
- 自动用户画像、情绪关系和陪伴式依赖。
- 用记忆替代任务事实、权限、质量门禁或用户当前指令。
- 首期建设复杂 Memory Hub、关系图谱或向量基础设施。
