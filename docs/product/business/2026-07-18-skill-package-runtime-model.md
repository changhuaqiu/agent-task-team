# Skill 包与 Agent 使用模型

> 日期：2026-07-18
> 状态：已确认，第一阶段实施中
> 关联规格：`specs/skill-package-progressive-loading/`

## 1. 用户问题

用户把一个 Skill 安装到 Skill 库、再绑定给团队成员后，必须能够回答三个问题：

1. 这个 Skill 是否完整安装；
2. 当前 Agent 是否真的获得了它；
3. 当前这次执行是否实际使用了它。

“数据库里存在一条 Skill 记录”或“页面显示已经绑定”都不足以证明 Agent 已经读到 Skill。

## 2. 核心对象

产品层只暴露四个对象：

| 对象 | 用户含义 |
| --- | --- |
| Skill 包 | 一项可安装、分享和版本化的能力资产 |
| 已安装 Skill | Skill 包的一个确定版本，出现在 Skill 库中 |
| Agent 能力绑定 | 哪些团队成员可以使用该 Skill |
| 本轮使用记录 | 本次执行实际加载了哪些 Skill |

“目录、内容 hash、上下文编译、运行时路径”等属于调试信息，不进入普通用户主流程。

## 3. 采用的用户流程

```text
导入 Skill 包
  → 校验目录和 SKILL.md
  → 安装一个不可变版本
  → 绑定给团队成员
  → 执行时编入 Agent 上下文
  → 调试页显示本轮使用证据
```

第一阶段中，**绑定即激活**：绑定给 Agent 的 Skill，其 `SKILL.md` 正文会在适用的上下文场景中由平台直接编入 Prompt。这样可以先建立确定性闭环，不依赖模型自行发现文件。

第二阶段才把“可使用”和“本轮激活”拆开：Agent 可以拥有多个 Skill，但平台只为当前任务选择少量 Skill。

## 4. Skill 包目录

Skill 包采用兼容 Codex Skills 的目录结构：

```text
skills/
└── <skill-name>/
    ├── SKILL.md              # 必需：触发描述 + 核心工作流程
    ├── agents/
    │   └── openai.yaml       # 可选：列表展示元数据
    ├── references/           # 可选：按需读取的领域知识
    ├── scripts/              # 可选：可执行的确定性流程
    └── assets/               # 可选：输出所需模板或素材
```

规则：

- `SKILL.md` frontmatter 只要求 `name` 和 `description`；
- `description` 必须同时说明“做什么”和“什么情况下使用”；
- `SKILL.md` 保留核心流程，详细知识进入 `references/`；
- 引用文件保持一层深度，并由 `SKILL.md` 明确说明何时读取；
- 不在 Skill 包内增加 README、安装说明、变更日志等辅助文档；
- `scripts/` 和 `assets/` 默认不作为 Prompt 正文加载。

## 5. 成功标准

第一阶段完成后：

- 用户可以从标准目录导入 Skill；
- Skill 库显示安装状态和版本；
- 用户可以把 Skill 绑定给 Agent；
- 每次执行可以证明 `SKILL.md` 正文是否已编入上下文；
- 调试页能区分“已绑定”和“本轮已加载”；
- Skill 附属资源不会被无差别塞入上下文。

## 6. 不做范围

第一阶段不做：

- Skill 市场、评分、推荐；
- 向量检索或复杂语义路由；
- 根据一次用户反馈自动修改正式 Skill；
- 要求各 CLI 使用相同的原生 Skill 发现机制；
- 在普通 Skill 配置页暴露内部上下文编译字段。

## 7. 关键产品判断

目录是 Skill 的作者与分发格式，不是跨运行时执行保证。真正的保证来自平台完成的安装、绑定、上下文编译和使用证据闭环。
