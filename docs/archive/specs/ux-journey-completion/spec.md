> Baseline: `59850ef`；审计：`docs/product/ux/2026-09-06-end-to-end-experience-audit.md`

## 目标与范围

落实体验审计 UX-01 至 UX-09。主线为“记录目标 → 交给团队 → 处理例外 → 查收成果”。兼容旧项目，不迁移或伪造历史完成证据，不改变 Agent 权限和终态门禁，不重做运行调度系统。

## 契约

1. 侧栏、项目卡片、工作区和项目内均消费 `projectWorkItems`。进行中只计算 `in_progress`；执行任务数另列。
2. 工作导航持有 Project、conversationId、taskId 的复合身份；旧项目共享空间也不丢目标。导航选中不等于打开任务操作抽屉。对象切换、外部通知和刷新不能错落到同空间另一项工作。
3. 当前任务阻塞与开放人工问题形成可解释的关注投影。历史交接回执只作为记录，不冒充当前状态；不修改根任务状态凑数。
4. 概览和工作项详情可直接打开阻塞任务；原因和恢复条件优先，危险/高级操作渐进展开。重试只表示请求已提交，不意味着权限已放开或执行成功。
5. 成果与验收由已有 Artifact、Task Gate、Project Review 和正式交付证据汇聚，只读展示来源、版本、时间、结论和缺口。旧数据缺证据明确告知，不解析聊天造结论。
6. 保留角色列和分类，补成果预览与关联工作导航。文件访问必须以项目内已登记对象为入口，拒绝越界、敏感文件和不支持类型；不执行文件内容。
7. 创建仅记录工作，不冒充已经开始。创建后提供明确团队安排入口，复用服务端 Human Command 与幂等回执；就绪状态、继承登录和职责使用用户语言。
8. 收件箱/活动可定位目标对象，保留消息/任务复合身份；待处理优先，可读正文按需展开；已读不等于已解决。
9. 用户术语统一为项目、工作项、执行任务、团队、交付件、验收；单一主创建入口，可键盘使用，长标题可读。发布、自动化、诊断保持可达，不强制进入主流程。

## 验证与退出

固定新旧工作项混合样本，比较数量一致性、导航正确性、阻塞定位操作数、验收来源可访问性、首用下一步与窄屏可读性。相关单元/组件/接口测试、类型检查、生产构建、浏览器验证、独立评审和桌面更新均完成；结果写入 C 级评测和 STORY。未做模型成对实验不得宣称 Agent 完成率提升。
