两条 prompt 管线收口 · 项目作用域隔离 · 跨项目只保留身份 · A2A 降级为上下文来源协议 ｜ 配套规格 specs/context-manager/spec.md ｜ 本期 P1+P2（记忆系统另立 spec）

核心收口：两条管线 → 一个出口

  • ① 主循环(user_turn) 与 A2A(a2a_handoff) 原各自组装 prompt、各算预算
  • ② 统一进 ContextManager.assemble()：scopeGuard → BudgetGuard → 输出
  • ③ PromptComposer 退为渲染器，renderDispatchPrompt 退役
  • ④ A2A 不再自建管线，只产出交接包作为 a2aHandoff source
  • ⑤ 预算/层优先级/作用域/身份 对两条路径统一
  • 对外契约不破：composeUserPrompt 仍返回 string

P1 / P2 分阶段路线

  • P1 · 非破坏先行（Toad 主责，后端 TDD）
  • 　T1 schema 只读排查（占位列） · T2 ContextManager
  • 　T3 Composer 委托 · T4 project{id} · T5 scopeGuard
  • 　T6 P1 测试 ｜ A2A 路径暂不动，并行运行
  • P2 · 迁移
  • 　T7 a2aHandoff source · T8 daemon 改调
  • 　T9 A2A 等价性测试 · T10 身份契约 · T11 占位列迁移
  • 　T12 P2 测试

范围边界（本期 vs 另立）

  • 本期 P1+P2：组装收口 / 项目作用域 / 跨项目身份 / A2A 协议化
  • 不在本期（YAGNI）：
  • 　跨会话 archival 记忆系统 → 另立 spec
  • 　embedding 语义相关性 → 沿用预留接口
  • 　LLM 摘要压缩运行时 → 沿用既有开关位
  • 　多项目并发会话产品级 UI → 只出契约+日志
  • 不改：A2A 持球/交接语义 · BudgetGuard · cli-bridge

四条验收指向（checklist 核心）

  • ① 主循环与 A2A 同走 ContextManager，共享 ContextBudget 与层优先级
  • ② 跨项目：项目 A 的 history/task 不出现在项目 B 的 prompt（scopeGuard 生效）
  • ③ 跨项目身份：同一 agent 多项目，身份段一致、项目段隔离
  • ④ A2A 降级：renderDispatchPrompt 退役，交接包经 ContextManager 注入，关键约束段不丢
